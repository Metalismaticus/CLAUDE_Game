Что просит владелец: **$ARGUMENTS**

(Если строка выше пуста или осталась без подстановки — взять из сообщения
владельца.)

Предел — это **потолок**, а не план. Сколько пунктов реально пойдут вместе,
решает разведчик `scout` по каждой партии: независимых пунктов может не
найтись ни одной пары, и тогда всё идёт по одному при любом пределе. Предел
только запрещает больше.

Настройка живёт в первой строке раздела «Параллельная работа»
`docs/TESTING.md`:

```
**Состояние: проверено · предел: 3**
```

## Без аргумента — показать

Одним коротким ответом: состояние, предел, чем и когда он проверен (строка
«Готово, когда … замер» раздела), число ядер процессора и сколько длится полная
проверка по таблице `docs/TESTING.md`. Ничего не менять.

## `N` — поставить

- **0 или 1** — всё по одному. Состояние не трогать: подготовка копий остаётся
  проверенной, её не придётся проверять заново, когда предел снова поднимут.
- **2 и больше** при состоянии «проверено» — записать предел. Если N выше
  того, что уже проверялось пробным прогоном, — одной строкой сказать, что
  одновременные полные проверки на этой машине с таким числом не мерились, и
  предложить `/parallel проверить`. Не отказывать: решение владельца.
- **2 и больше** при состоянии «не проверено» — записать предел и сказать, что
  он не заработает, пока копия не проверена: это кусок пункта «Построить
  проверки» в очереди или `/parallel проверить`.
- **«невозможно»** — записать предел нельзя без пересмотра причины, записанной
  в разделе; назвать её.

Больше числа ядер процессора предел не ставить без прямого «да, всё равно»:
проверки начнут мешать друг другу, и ложные провалы съедят выигрыш.

## `проверить` — пробный прогон

Только в чате разработки и только вне партии (`docs/BATCH.md` — «Пусто.»).
Идёт долго: сказать владельцу, сколько примерно, и дождаться «да».

1. Создать N копий по разделу 3а `/start` (`git worktree add … -b trial/pK
   main`), подготовить каждую по «Подготовке копии».
2. Прогнать полную проверку во всех копиях **одновременно** (фоновые команды),
   в контекст — только итоговые строки и время.
3. Сравнить с одиночным полным прогоном в основной папке:
   - результаты совпадают — нет ложных провалов;
   - данные каждой копии легли отдельно, основная папка не тронута;
   - время одной проверки выросло не больше чем вдвое.
4. Убрать копии и ветки.
5. Записать в раздел: наибольшее N, при котором всё верно, — предел; дату и
   числа замера — в «Готово, когда». Проверки, которые покраснели только при
   одновременном прогоне, — в «Нельзя одновременно».

## Сохранить

Изменение одной строки `docs/TESTING.md` — отдельный документальный коммит,
файл поимённо; отправить, если в `CLAUDE.md` коммиты отправляются. Идёт партия —
новый предел действует со следующего `/start`: волны текущей партии уже
сняты.
