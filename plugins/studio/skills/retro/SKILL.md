Что разбираем: **$ARGUMENTS**

Разбор делается по следам в git и документах, а не по памяти чата: к моменту
`/retro` подробности партии из контекста уже ушли.

## 1. Собрать факты

За последнюю принятую партию (от коммита, где она записана в `docs/BATCH.md`,
до завершающего документального коммита `/done`):

- `git log --grep "Пункт"` — сколько коммитов у каждого пункта; коммиты
  «поправка — …» и revert-коммиты;
- история `docs/BATCH.md` (`git log -p -- docs/BATCH.md`): состояния
  `не выполнен`, `ждёт`, замечания проверяющего, строки «Ограничение», «Свои
  числа», «Найдено по ходу»;
- непринятые пункты в «Очереди» `docs/ROADMAP.md` — слова владельца при них.

## 2. Найти повторяющееся

Один случай — случай. Урок — то, что случилось дважды или стоило дорого:

| След | О чём говорит |
|---|---|
| поправка владельца по виду | в `docs/DESIGN.md` не хватает правила или `designer` не видел настоящих данных |
| поправка по поведению | критерий готовности был написан про код, а не про то, что видит пользователь |
| три круга без одобрения | пункт слишком велик или критерий нельзя проверить |
| откат из-за зависимости | в партию взяли два пункта про одни файлы |
| «ждёт» с вопросом, ответ на который был в документах | документ трудно найти или он устарел |
| свои числа, которые владелец потом менял | эти числа надо спрашивать до работы |
| красное на нетронутой проверке | проверка хрупкая — это пункт очереди |

## 3. Развести уроки по адресам

- **Урок проекта** — правило про этот продукт или стек. Черновик строки для
  `docs/DECISIONS.md`, раздел «Уроки партий», или для `docs/DESIGN.md`, или для
  «Правил проекта» в `CLAUDE.md`.
- **Урок процесса** — годится для любого проекта: команда плагина что-то не
  спросила, не проверила, разрешила лишнее. Черновик для
  `docs/PLUGIN-FEEDBACK.md`: какая команда или агент, что случилось, какая
  правка текста предлагается. Этот файл владелец переносит в репозиторий
  плагина; сам плагин отсюда не править.

## 4. Показать и дождаться

Показать владельцу: факты одной таблицей, затем уроки — не больше пяти, каждый
с адресом и готовой формулировкой. Партия прошла чисто — так и сказать одной
строкой и ничего не выдумывать.

После подтверждения внести принятые уроки в документы одним документальным
коммитом, файлы поимённо. Пункты очереди из уроков (хрупкая проверка, большой
пункт разбить) — не ставить самому, а записать в `docs/BATCH.md`, «Найдено по
ходу»: очередь ведёт чат замысла.
