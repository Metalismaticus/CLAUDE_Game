# 3а. Волна: пункты одновременно

Глава протокола `/start` — читать, дойдя до этого этапа; после сжатия контекста перечитать. Пути — от базовой папки скилла (там лежит `SKILL.md`), как в нём; «раздел N» — глава `steps/N.md`.

Каждый пункт волны — в своей копии из **набора копий**: git worktree
`../<папка проекта>.wt/slot<K>` на ветке `wave/p<N>`; основная папка и `main`
не меняются, пока пункт не одобрен. Копия видит только закоммиченное, поэтому
порядок строгий:

1. `[ui]` волны — `designer` в основной папке, итог — по разделу 3, п. 2:
   все сразу, если в `docs/TESTING.md` нет команды снимка, иначе по одному;
   каждый пишет только свой файл в `docs/specs/`.
2. **Коммит партии до копий:** `docs/BATCH.md` (партия, пункты волны `в работе
   · круг 1/3`) и спецификации волны поимённо, сообщением `Партия: волна W —
   пункты N, M`. Без него исполнитель в копии прочтёт прошлую партию.
3. Слот на каждый пункт N — через **пул слотов**: `python -X utf8
   tools/slot_pool.py acquire --item p<N>` печатает путь слота
   (переиспользует чистый слот и переключает его на ветку `wave/p<N>`; нового
   нет — создаёт; слот с остатками помечен dirty и не отдаётся; предел —
   `pool.max_slots` в `tools/check_plan.json`; перед созданием — проверка
   свободного места). **Код 3 — «мало места»**: остановить партию с
   напечатанной причиной, без повторов; это не красное. Слот — ресурс
   исполнения, не номер пункта. Слот пункта `ждёт` — `slot_pool.py park
   <слот> --reason "<вопрос>"` (ответ пришёл — `unpark`), в строку пункта:
   `ждёт: … · слот K`; слот с незакоммиченным до ответа не брать (пул его и
   не отдаст). После обрыва или сжатия контекста — `slot_pool.py sync`:
   восстанавливает учёт из `git worktree list`, его отчёт — в контекст
   итоговыми строками. Нет скрипта или `tools/check_plan.json` (старый
   проект) — прежний способ: `git worktree add -b wave/p<N> "<слот>" main`,
   прежний слот сбросить по «Набору копий» `docs/TESTING.md`, старую ветку
   слота удалить (`git branch -d`, снятую сбоем — `-D`); в отчёт — строка
   «`/setup обновить`».
4. Всех `executor` волны — **одновременно** (несколько вызовов Agent в одном
   сообщении), не больше `пишут`: «Пункт N партии из `docs/BATCH.md`. Работай
   только в копии `<полный путь слота>`: сначала подготовь её по
   `docs/TESTING.md`, «Параллельная работа»», для `[ui]` — путь спецификации,
   для `[вид]` — шаг и полный путь библиотеки приёмов
   `../../reference/LOOK_TECHNIQUES.md` (раздел 3, п. 3).
5. Итоги волны приходят вместе: `reviewer`-ов — одним сообщением по разделу
   3, п. 5–6, с путём копии (файлы снимать из неё). **Тяжёлые** — полные и
   со снимками (`[вид]`, пункт про вид): видеокарта одна, их разом не больше
   `тяжёлых проверок`, остальные — как освободится; снимки `executor` по ходу
   — без очереди, это не замер. `docs/BATCH.md` ведёт только координатор в
   основной папке; в копиях его не править и не коммитить. Проверки в копии
   при заполненном `tools/check_plan.json` (список `checks`) — единым входом
   `python -X utf8 tools/run_check.py --root <полный путь слота> --mode
   <quick|item|affected>` (сборочный каталог на слот ставит он; руками
   `CARGO_TARGET_DIR` не выставлять); план пуст — по таблице
   `docs/TESTING.md`, как раньше.

**Слияние — строго по одному, в порядке очереди**, по мере одобрения:

1. В копии: коммит файлов пункта поимённо, сообщение — по разделу 3, п. 7;
   `git rebase main` (конфликт — `git rebase --abort`, «Сбой волны»); `main`
   успел измениться — быстрая и проверка пункта, красное — «Сбой волны».
2. В основной папке: `git merge --ff-only wave/p<N>`, быстрая проверка;
   красное — `git revert --no-edit` коммитов пункта, «Сбой волны».
3. В `docs/BATCH.md` — `готов к проверке` и строки по разделу 3, п. 7; коммит
   `Партия: пункт N готов к проверке`; отправить, если коммиты отправляются.
   Слот — `slot_pool.py release <слот>`: остаётся в пуле чистым, кэш сборки
   переживает пункты (у `[вид]` — после слияния «встроить», не основы).

**`[вид]` в копии** вливает одобренную основу (`основа —`) так же, затем в
том же слоте идёт выбор. **Исключение из порядка очереди:** после слияния
основы пункт очередь не держит — следующие вливаются, пока идёт его выбор;
коммит вариантов ждёт в `wave/p<N>`. После выбора (3б, п. 3) — в слоте `git
rebase main`, «встроить вариант X», слияние. Конфликт или красное — «Сбой
волны», но повтор — с «встроить» в основной папке: `executor` получает `git
show` коммита вариантов, выбор — в «Журнале».

Слоты в конце запуска остаются в пуле (кэш сборки переживает пункты; слот
нужен и поиску виновника, раздел 6): после раздела 6 удалить только ветки
`wave/p<N>` влитых пунктов (`git branch -d`); места мало — `slot_pool.py
clean-cache --free` (кэши свободных слотов), лишние каталоги покажет
`slot_pool.py diagnostics` (только пути и размеры); слот с незакоммиченным
— в отчёт, не удалять. Старый проект без пула — как раньше: `git worktree
remove`, `git branch -d`. Проверки из «Нельзя одновременно» —
только в основной папке, по одной; снимки стенда — в копии пункта, как
тяжёлые (п. 5): строка «снимки стенда — по одному» старых проектов — о том же.

**Сбой волны** — пункт не так независим, как обещал `scout`: вернуть его
`ждёт очереди` с пометкой «повтор по одному: <причина>» и сделать **после**
волны по разделу 3, с нуля; в «Найдено по ходу» — в чём ошибка прогноза
(неназванный общий узел — для «Общих узлов» `docs/TESTING.md`). **Ложные
провалы** (красное в копии, зелёное в основной папке) — до конца партии всё
по одному; в «Найдено по ходу» — снизить `пишут` или дописать «Нельзя
одновременно».
