# 2. Зафиксировать объём

Глава протокола `/start` — читать, дойдя до этого этапа; после сжатия контекста перечитать. Пути — от базовой папки скилла (там лежит `SKILL.md`), как в нём; «раздел N» — глава `steps/N.md`.

Перечитать «Очередь» в `docs/ROADMAP.md`: чат замысла мог её поменять.

- Обычный `/start` — ровно один пункт. `/start all` — один раз снять все
  пункты `[можно]`; найденное по ходу — в «Найдено по ходу» и в отчёт, партию им
  не расширять. Строка `scout` «Узкое место» — туда же и в отчёт словами
  продукта («все пункты шли по одному из-за общего файла проверок»).
- **Уборки** (пункты `Уборка:`) — не больше двух и не больше половины партии
  (в партии из 1–3 пунктов — одна). Первой — уборка, которая стоит перед
  пунктом партии или `[ждёт уборки]` и правит его файл (без неё — «не
  удалось: код»), даже второй общий узел (таких — обе уборки, по одной в
  волне); сам `[ждёт уборки]` — в ту же партию волной после неё (`scout`:
  «зависит от M»), не дожидаясь `/done`; дальше — первые по очереди, из них
  уборка общего узла (реестр или раннер, базовый класс, схема данных,
  корневой файл, «Общие узлы» `docs/TESTING.md`) — одна; остальные ждут
  следующей — строкой в отчёт. Без предела — если, кроме уборок, `[можно]`
  ничего нет, и по `/start all уборка` («сделай уборку»). `Уборка:` с двумя
  «Не выполнен» в подробностях не брать: строкой `уборка: пересмотреть
  «Готово, когда» — <пункт>` в «Найдено по ходу» (цель и критерий — `/idea`);
  с двумя «Пересмотрен» — не отдавать: её и `[ждёт уборки]` покажет `/board`.
  Строки с `уборка:` (исполнителя, «Вне круга» проверяющего, «Узкое место»
  разведчика, `code_check`) — в «Найдено по ходу» по строке на уборку, каждая
  с `уборка:` в начале (префикс «Вне круга:» убрать): по нему их узнаёт `/idea`.
- Названный пункт заблокирован вопросом, файлом или проверкой владельца —
  объяснить; другой брать только при пустом `/start` или `/start all`.
- `[предварительно]` — одиночный `/start` подтверждает окном до работы, не
  подтверждён — не брать. `/start all` берёт его, только если на оговорку
  есть «да» в `docs/DECISIONS.md` (в отчёт — «по вашему «да» <дата>»); иначе
  пропускает и, если строки ещё нет, пишет в «Решения» `BLOCKED.md` «<пункт>:
  «<оговорка>» — делать так? — /need» (в коммит снятия партии).
- Нет метки маршрута — определить по «Маршруту» `../idea/steps/7.md` и записать
  в партию. `[вид]` без условий 3б, п. 1 не брать (`[ждёт света]` — тоже;
  тем `[вид]` на партию — не больше, чем велит строка «Стенда»
  `docs/TESTING.md`, у проекта с недельным лимитом — одна); `[ощущение]` —
  не больше одного на тему, второй той же темы ждёт следующей партии.

Записать партию в `docs/BATCH.md` по образцу из его шапки: строки шапки (с
«Последний полный прогон: не было», «Волны: —», «Язык коммитов: <из «Git»
`CLAUDE.md` или по «Язык» `COMMITS.md`>»); таблица — номер, волна,
пункт с метками, критерий, `ждёт очереди`. Номера стабильные — на них
ссылается `/done кроме 3`.

**Проверка партии** — `python -X utf8 tools/batch_check.py` после записи
партии и ещё раз после записи волн. Код 0 — в порядке; код 1 — находки
строками (партия внутри комментария-образца, «Пусто.» рядом с живой партией,
повтор номера, параллельная партия без строки «Волны (от `scout`)» или пункт
«в работе» вне волн, слот на двух пунктах) — исправить до запуска агентов;
код 2 или нет скрипта — строка в отчёт «`/setup обновить`».

**Волны** — после записи (`scout` читает партию из файла). `пишут` — из
аргумента, иначе из «Параллельной работы» `docs/TESTING.md` (`предел: N` =
`пишут: N`). Пунктов больше одного и `пишут` больше 1 — свежий `scout` с
номерами и `пишут`; его волны с причинами — как есть в шапку и столбец
«Волна», других пар не собирать. Волны идут всегда, когда `пишут` > 1 и
`scout` подтвердил независимость: состояние «проверено / не проверено» —
справка о пробном прогоне, не ворота; при «не проверено» — строка в отчёт
«первый параллельный прогон — калибровка: диск покажет `slot_pool.py
diagnostics`, время по пунктам — `/retro`» (раздел 6); «невозможно» —
по-прежнему всё по одному с причиной из раздела `docs/TESTING.md`. Иначе
каждый пункт — своя волна.

**Нарезка — до запуска.** Пункт делается одним исполнителем, когда он мал:
около четырёх кусков «Готово, когда», до шести файлов по прогнозу `scout`,
одна система, и никогда — смена формата данных вместе с новой системой.
Больше — кусками по «Подробностям» пункта (`docs/ROADMAP.md`) и по прогнозу
`scout` («велик: кусками»): каждый кусок — свой цикл раздела 3 (исполнитель →
проверяющий, в строке пункта `· кусок k/K`) и свой контрольный коммит
(`Пункт N: <что изменилось>`), `готов к проверке` — после последнего; кусков
в «Подробностях» нет — координатор режет сам, техническое решение, строка
«Решил сам: пункт N — кусками: <какими> — <почему>» в «Принято по умолчанию».
Это эвристика планирования, а не повод плодить отдельно проверяемые
файлы-помощники. **Число в критерии — только с источником**: слова владельца,
паспорт образца, существующая проверка, доказанный инвариант; число без
источника (константа настройки, зажим, догадка) — не блокирующее требование:
назвать в «Решил сам» как гипотезу, исполнителю оно — диагностическое, не
критерий.

Партия может задеть данные пользователя (`docs/TESTING.md`) — снять копию,
как там сказано, и записать в шапку. До первого пункта — **исходная
проверка** (с ней видно, какой пункт сломал прогон): для `/start all` полная,
для одного пункта быстрая; полигон не «есть» — выполнить, что есть, и
записать, чем ограничена проверка. Красная основа — остановиться и показать
провал, если это не намеренно красная проверка из `docs/BUGS.md`.
