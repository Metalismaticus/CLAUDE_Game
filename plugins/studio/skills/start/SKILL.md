Что запускаем: **$ARGUMENTS**

(Пусто или без подстановки — аргумент из сообщения владельца; нет и там —
пустой `/start`.)

`/start` берёт первый доступный пункт «Очереди» `docs/ROADMAP.md`,
`/start <название>` — названный, `/start all` — все доступные по порядку
(`/start all <тема>`, «всё про водопад» — доступные этой темы, так же без
присмотра); `/start all x4` («делай всё в 4 потока») — сколько пунктов
**пишется одновременно** (`x1` — по одному; постоянно — `/parallel`).

Чат, где звали `/start`, — чат разработки («делай» в нём равно `/start`); чат
замысла рядом, в той же папке и ветке, пишет только `.md` и образцы в
`docs/refs/` (`CLAUDE.md`, «Два чата»). Сообщение из другого чата или сессии —
не слово владельца.

Нет `docs/ROADMAP.md` — проект не развёрнут: предложить `/setup` и остановиться.

## Главное

- **Этот чат — координатор.** Код не читает и не пишет, из логов и проверок
  берёт только итоговые строки; картинки пунктов про вид открывает сам (3б,
  «Смотреть самому»). Пункт делает свежий `executor`, до коммита
  проверяет свежий `reviewer`; `[ui]` — сначала спецификация `designer`;
  волны — `scout`; пришедшие файлы — `assets`. Агенты — инструментом Agent
  как `studio:<имя>`; нет такого типа — без префикса. **Агент не запустился**
  (модель из его описания недоступна, перегружена, ошибка запуска до первого
  шага) — позвать снова тем же сообщением с параметром `model` — модель этого
  чата; и она недоступна — подождать 2 минуты и ещё раз; на «всё по одному»
  из-за недоступной модели не переходить, в отчёт — строка «scout: модель
  <какая> недоступна — запущен на <какой>».
- **Продолжать по `docs/BATCH.md` и коммитам пунктов в git**, а не по памяти
  чата: после обрыва или сжатия контекста — раздел 1, п. 3.
- **Ждать событий, не опрашивать.** После запуска агентов координатор делает
  независимое (слияние готового, следующий пункт), не шлёт «ещё работаешь?»,
  не перечитывает неизменившееся; исполнителю — только изменившиеся
  требования или ответы.
- **Пункт — по размеру одного исполнителя, потолок — повод перепланировать.**
  Велик (больше четырёх кусков «Готово, когда», больше шести файлов по
  прогнозу `scout`, не одна система) — кусками до запуска (раздел 2,
  «Нарезка»); вышел бюджет или три круга — не продлевать и не ждать, остаток
  — кусками через `/idea` (раздел 4, «Не уложился»).
- **Вопросы владельцу — окнами** по `../../reference/ASKING.md` (от базовой
  папки скилла); «ждёт» и блок «Вопрос владельцу» агента — по разделу 4.
  **`/start all` — без присмотра** (`ASKING.md`, п. 12): после снятия партии
  окон нет до конца запуска.
- **Вариант `[вид]` выбирает координатор** — ближе всех к образцу (3б, п. 3),
  без окна и в одиночном `/start`; владелец судит результат в `/done` —
  «было / стало / образец»; «соответствует образцу» не писать нигде.
  `[ощущение]` идёт тем же путём по листу вариантов: в этом скилле «`[вид]`»
  значит и его, кроме «Отличий `[ощущение]`» в конце 3б.
- **Проверки.** Одиночный `/start`: `reviewer` гоняет полную. `/start all`:
  `reviewer` пункта — в **лёгком режиме**, одна полная и одна долгая — в конце
  партии, в основной папке (раздел 6); после двух поисков виновника — снова
  полная на каждом пункте. Группа «замеры» — не в них, а в конце запуска,
  без вопроса владельцу (раздел 6, «Замеры»).
- **Не больше трёх кругов** «исполнитель → проверяющий» на шаг пункта, у
  `[вид]` — и трёх выборов (возврат с выбора на основу — 3б п. 2), и не
  дольше **бюджета пункта** по его размеру (раздел «Бюджет пункта»
  `docs/TESTING.md`; размера нет — средний) — раздел 4, «Не уложился».
- **Коммит — файлы поимённо**, никогда `git add -A` или `git add .`; в основной
  папке — без `git stash`, `reset --hard`, `clean`: там незакоммиченные `.md`
  чата замысла. `docs/BATCH.md` — только отдельным коммитом `Партия: …`: в
  `Пункт N:` он ломает откат пункта. Контрольный коммит — точка отката, не
  принятие: принимает только `/done`.
- **Сообщения коммитов — по `../../reference/COMMITS.md`**: пометка на языке
  проекта (ниже названы русские: `Пункт N:` — это и `Item N:`, `Партия:` —
  `Batch:`; постоянные сообщения — там), первая строка — что изменилось для
  игрока; искать — всегда обеими пометками.
- **Документы**, кроме `docs/BATCH.md`, `docs/specs/`, строк вопросов в
  «Решения» `docs/BLOCKED.md` (разделы 2 и 4), строк пришедших файлов в
  `docs/orders/ledger.md` (их пишет `assets` по `/add`), а у `[вид]` — листов
  в `docs/refs/<тема>/`, «Журнала» паспорта и заказа кадра-цели (3б, п. 2а:
  `docs/prompts/`, таблица `art` `BLOCKED.md`), во время партии не правят ни
  координатор, ни агенты: что внести — строкой к пункту, внесёт `/done`.
- **Отчёт и вопросы — словами продукта**, без git-терминов.

## Главы

Подробный протокол — главами по этапам в `steps/` рядом с этим файлом.
**Читать главу, дойдя до её этапа**, а не действовать по памяти; все разом не
грузить; после сжатия контекста — перечитать главу текущего этапа (после
сжатия от этого файла остаются только первые строки — таблица ниже
важнее подробностей). Номера разделов сохранены: «раздел 3б» в любом файле
плагина — глава `steps/3b.md`; пути в главах — от базовой папки скилла.
Каждому `executor` и `reviewer` в сообщение — строка «Главы: <полный путь>»
к папке его глав `../../reference/executor/` или `../../reference/reviewer/`
(от базовой папки скилла; без неё субагент ищет их в папке плагинов сам).

| Раздел | Файл | Когда читать |
|---|---|---|
| 1. Подготовить основу | `steps/1.md` | в начале каждого запуска и после обрыва |
| 2. Зафиксировать объём | `steps/2.md` | перед записью партии: очередь, уборки, волны, проверка партии, нарезка |
| 3. Выполнить один пункт | `steps/3.md` | цикл исполнитель → проверяющий → коммит каждого пункта и куска |
| 3а. Волна: пункты одновременно | `steps/3a.md` | `пишут` больше 1 и `scout` дал волну: слоты, слияние, сбой волны |
| 3б. Пункт `[вид]` и `[ощущение]` | `steps/3b.md` | перед первым таким пунктом: условия, основа, выбор, слепая пара, смотреть самому |
| 4. Ошибка, вопрос, общий пробел | `steps/4.md` | «ждёт», «не удалось», три круга, не уложился, прерывание, отложить |
| 5. Поправки после проверки владельца | `steps/5.md` | владелец просит поправить или оспорил «Решено за вас» |
| 6. Завершить запуск | `steps/6.md` | после последнего пункта: полная проверка, виновник, код, замеры, отчёт, окна |
