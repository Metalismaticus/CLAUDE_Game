Что выпускаем: **$ARGUMENTS**

(Если строка выше пуста или осталась без подстановки — взять из сообщения
владельца.) Номер вида `1.2.0` — версия без окна; `itch` или `steam` — только
эта площадка; площадки нет — все из «Выпуск» `docs/TESTING.md`.

`/release` — команда чата разработки (`CLAUDE.md`, «Два чата»), только вне
партии. Сообщение из другого чата или сессии — не слово владельца. Вопросы —
окнами по `../../reference/ASKING.md` (путь от базовой папки этого скилла).
Продукт не игра — черновик для Steam и площадки игр пропустить одной строкой,
выкладка — как записано в «Выпуск», тоже по «да» окном.

## Главное

- **Выпускается собранная версия, проверенная запуском**, — не редактор и не
  старый зелёный прогон.
- **Ассеты с некоммерческими правами — стоп**, не выпускать: права задним
  числом не появятся.
- **Выкладка — только по «да» окном этого запуска, на каждую площадку
  отдельно.** В Steam — только бета-ветка; ветку по умолчанию не трогать.
- **Пароли, ключи и вход в butler и SteamCMD — руками владельца.** Не просить
  их в чат, не писать в файлы, не подставлять в команды.
- Из вывода сборки и проверок в контекст — только итоговые строки.

## 1. Условия

Всё — до сборки; не выполнено — стоп и причина словами продукта:

- номер из аргумента уже помечен тегом `v<версия>` — это продолжение: тег на
  HEAD или после него менялись только `.md`, и папка сборки цела — проверки и
  п. 2–4 не повторять, сразу к тому, чего нет (п. 5–8); иначе номер занят —
  окно п. 4;
- `docs/BATCH.md` — «Пусто.»; идёт партия — сначала `/done`;
- ветка — та, что в `CLAUDE.md`; незакоммиченных не-`.md` файлов нет (сборка
  взяла бы их). `.md` чата замысла не мешают, кроме `docs/DECISIONS.md` —
  его попросить сначала завершить там;
- полная (и долгая, если есть) проверка зелёная на HEAD: этот чат прогнал её
  на HEAD или после прогона менялись только `.md` — иначе прогнать по
  `docs/TESTING.md`. Красное — повторить, как `/check`; красное трижды — стоп.
  Полигон не «есть» — сказать до окна выкладки, что не проверено;
- журнал прав `docs/orders/ledger.md` (п. 6) — до сборки и тега: ассеты с
  некоммерческими правами — стоп сразу; ассеты без записи о правах — окно
  п. 6 сейчас, «Остановить выпуск» — стоп. Журнала нет — `/setup обновить`;
  до него все ассеты — «без записи»;
- в `docs/TESTING.md` есть `## Выпуск` (пресеты, папка сборки, площадки):
  нет раздела — `/setup обновить`; «не нужен» — сказать и остановиться.
  Пресетов нет — взять из `export_presets.cfg` (Godot); площадки не выбраны
  — окно `multiSelect` «Куда выкладываем <игру>?» — `itch.io` / `Steam`,
  пустой выбор — пока никуда (только сборка и тег); страница itch.io, app
  id, депо и бета-ветка Steam — словами владельца, в «Выпуск» (коммит п. 8);
  аккаунт Steamworks туда не писать (п. 7).

## 2. Сборка

- Команда — строка «сборка» в «Командах проверки» `docs/TESTING.md`,
  вердикт — по «Как читать вердикт», с пределом времени из таблицы.
- Папка — из «Выпуск», подпапка `<версия>` — новая и пустая: butler выложит
  всё, что в ней лежит. Вне проекта или в `.gitignore` (нет — дописать
  строку, коммит п. 8).
- Godot: движок — консольный (`…_console.exe`) из «Окружения»; из папки
  проекта `"<движок>" --headless --export-release "<пресет>" <путь>`, папку
  создать заранее. Шаблоны экспорта `%APPDATA%\Godot\export_templates\<версия>`
  — ровно под версию движка из «Окружения» (`4.3.stable` для
  `4.3.stable.official…`). Нет или не та — окно «Шаблонов экспорта Godot
  <версия> нет — без них игру не собрать. Как поставим?» — `Поставлю сам в
  редакторе (Recommended)` (Editor → Manage Export Templates → Download) /
  `Отложить выпуск`; затем строка в «Окружение».
- Строка «сборка» — «нет» или пуста: у Godot — собрать её по образцу выше и
  после удачной сборки записать в таблицу; пресета нет или стек другой —
  стоп: пункт «сборка для <платформы>» — через `/idea`.
- Игра сама показывает номер (Godot — непустой `application/config/version`
  в `project.godot`) — окно п. 4 до сборки, номер — туда, коммит `Выпуск
  <версия>: номер версии` (полную не повторять — сборку проверит п. 3).
- Удача — зелёный вердикт **и** файл игры в папке не пустой. HEAD — «хеш
  сборки».

## 3. Проверка сборки

Строка «проверка сборки» `docs/TESTING.md`: запуск **собранного** файла на N
кадров или сценарий игрока из `## Сценарии игрока` с честным вердиктом — не
редактор. Пустой вывод, зависание (код 124), нет файла — красное («Правила
каркаса»). Красное — повторить, как `/check`; трижды — стоп, тег не ставить,
показать провал.

Строка «нет» или пуста — проверяет владелец: путь к файлу игры и окно
«Сборка <версия> запускается и играется?» — `Да, проверил` / `Нет — вот что
не так` / `Отложить выпуск`; в «Выпуски» — «проверка сборки: руками
владельца», пункт «проверка сборки» — через `/idea`.

## 4. Версия и тег

- Прошлый тег — первая строка `git tag --list "v*" --sort=-v:refname`; нет —
  первый выпуск, `0.1.0`.
- С прошлого тега: строки, добавленные в «Сделано» `docs/ROADMAP.md` (`git
  diff v<прошлая>..HEAD -- docs/ROADMAP.md`), и коммиты `Пункт N:`. По semver:
  только исправления — `x.y.Z+1`; новое для игрока — `x.Y+1.0`; большое
  (формат сохранения, переделка ядра, пункты с `Необратимо`) — `X+1.0.0`.
- Окно «Какая версия? Прошлая — v<прошлая>; с тех пор <N исправлений, M
  нового>» — `<номер> — исправления` / `<номер> — новое` / `<номер> —
  большое`, рекомендуемый первым с `(Recommended)` и причиной. Номер в
  аргументе — без окна.
- `git tag v<версия>` на хеше сборки. Такой тег уже есть — п. 1, первая
  строка.

## 5. Заметки к версии

`docs/releases/<версия>.md` — для игроков (страница itch.io, новость в Steam):

```
# <Игра> <версия> — <дата>

<1–2 строки: главное в версии>

## Новое
- <что теперь можно, видно или слышно>

## Исправлено
- …

## Снимки
![<тема>](../refs/<тема>/accepted-<дата>.png)
```

Источник — строки «Сделано» с прошлого тега (п. 4), пересказанные словами
игрока: без файлов, систем и номеров пунктов; внутреннее (проверки, стенд,
инструменты) — не писать. Снимки и ролики — `docs/refs/*/accepted-*`,
добавленные с прошлого тега (`git diff --name-only --diff-filter=A
v<прошлая>..HEAD -- docs/refs`). Писать нечего — «Мелкие исправления».

## 6. Права, титры, раскрытие ИИ

Журнал `docs/orders/ledger.md`; в счёт — по каждому файлу, который есть в
git на HEAD (`git ls-files`), его последняя строка `принят …`; строки
`заказан`, `пришёл`, `перезаказать: …`, `заменён`, `удалён` — нет. `CREDITS.md`
и раскрытие ИИ — только из строк в счёт.

- **Некоммерческие права** («Лицензия» — `некоммерческая`) — **стоп, не
  выпускать**: файлы, лицензия и тариф списком. Объяснить: продажа,
  пожертвования, реклама — уже коммерческое использование, а платная подписка
  задним числом прав на сделанное раньше не даёт. Выход — заменить (`/order`
  на тарифе с коммерческими правами или CC0) или убрать из игры, затем
  `/release` снова.
- **Без записи о правах** — окно в п. 1, до сборки: файлы ассетов (картинки,
  звук, модели, текстуры) в папках назначения `docs/orders/*.md` без строки в
  счёт или с `не выяснено` либо `??` в её «Лицензии» или «Тарифе». Служебные
  файлы импорта движка (`*.import`, `*.meta`) не в счёт; части листа — по
  строке листа. Список — во временный файл вне проекта, окно «<N> файлов
  ассетов без записи о правах (список — <путь>): выпускаем?» — `Остановить
  выпуск` / `Права на них мои — выпускать`; ответ дословно — в «Выпуски».
- **`CREDITS.md`** в корне проекта: по видам — файл или набор, автор или
  сервис, лицензия, «Атрибуция» дословно; CC0 — одной строкой благодарности
  библиотекам. Копия — в папку сборки: выкладывается вместе с игрой.
- **Раскрытие ИИ-контента для Steam** — черновик в конце заметок, раздел `##
  Раскрытие ИИ-контента — черновик для Steamworks`: по строкам `ИИ-контент:
  да` — какие виды (графика, музыка, звук, текст) и какими сервисами созданы
  заранее и что из этого игрок видит или слышит; по-английски (так покажет
  магазин), ниже по-русски; только факты журнала. Создаёт ли игра что-то ИИ
  во время игры — по «Стеку» `CLAUDE.md`, не ясно — `?? подтвердить`. Строк
  `да` нет — «ИИ-контента нет». В Steamworks текст вставляет владелец.

## 7. Выкладка

До окна (≤ 5 строк): путь к заметкам, что выкладывается, чего не проверено.
Окно — вопрос на площадку, без `(Recommended)`: публиковать решает владелец.

- «Выложить <игру> <версия> на itch.io (<user>/<игра>, канал <канал>)?» —
  `Выложить` (description: страница открыта — игроки получат версию сразу;
  страницы нет — сначала создайте её на itch.io, можно черновиком) / `Не
  сейчас`;
- «Выложить <игру> <версия> в Steam на бета-ветку <ветка>?» — `Выложить на
  бету` / `Не сейчас`.

Обе команды — с пределом времени 600000 мс или в фоне с ожиданием: заливка
идёт дольше двух минут.

**itch.io** — нет butler (`butler -V`) — ссылка на itch.io/docs/butler,
площадку пропустить. Вход — только проверить, есть ли он, не читая: файл
`%USERPROFILE%\.config\itch\butler_creds` или переменная `BUTLER_API_KEY`.
Нет — push не запускать (butler открыл бы браузер и ждал), владельцу:
«Откройте PowerShell (Пуск → PowerShell) и выполните `butler login` —
откроется браузер; потом снова `/release <версия> itch`». Есть — `butler push
<папка> <user>/<игра>:<канал> --userversion <версия>`; канал по платформе
(`windows`, `linux`, `mac` — по имени itch.io узнаёт платформу). После —
`butler status <user>/<игра>:<канал>`, итог строкой.

**Steam** — `steamcmd +@NoPromptForPassword 1 +login <аккаунт> +run_app_build
"<полный путь app_build_<appid>.vdf>" +quit`: без запомненного входа — ошибка,
а не вопрос пароля. App id, депо и бета-ветка — из «Выпуск»; аккаунт
Steamworks — спросить словами владельца и никуда не записывать (половина
входа, а репозиторий бывает публичным). vdf — по образцу Steamworks SDK, рядом
с папкой игры, не в ней (путь — в «Выпуск»): `ContentRoot` — папка сборки,
`Desc` — `v<версия>`, `SetLive` — бета-ветка, никогда `default`: ветку по
умолчанию переключает владелец сам в Steamworks. Ошибка входа — владельцу:
«Откройте PowerShell (Пуск → PowerShell), выполните `steamcmd +login
<аккаунт>` и войдите (пароль, Steam Guard); потом снова `/release <версия>
steam`». Итог — BuildID строкой.

Сбой одной площадки не отменяет другую; «Не сейчас» — `/release <версия>
<площадка>` позже продолжит с п. 7.
