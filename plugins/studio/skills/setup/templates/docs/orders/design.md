# Заказ: макет экрана (`design`)

Макет заказывается, когда экрана ещё нет или он не получается: `designer`
пишет спецификацию словами и числами, а макет показывает, **как это должно
выглядеть**. Правила интерфейса — в `docs/DESIGN.md`; здесь — только как
заказывать.

## Паспорт

| Поле | Значение |
|---|---|
| исполнитель | {{claude-design \| вручную}} |
| проект в Claude Design | {{название и projectId — записывает первый `/order design`}} |
| куда сохранять | `design/mockups/<экран>/` |
| формат | HTML и снимок PNG |
| файлы заказов | `docs/prompts/design-NN.md` |

## 1. Что уходит в Claude Design

Дизайн-система проекта, собранная из `docs/DESIGN.md` в `design/system/`:
цвета и типографика, сетка, готовые компоненты с их состояниями. Она
выгружается инструментом `DesignSync` — **по одному компоненту, только
изменившееся**, никогда целиком поверх. Выгрузка идёт по плану, который
владелец видит и утверждает.

Задачу в Claude Design поставить отсюда нельзя: инструмент умеет только читать
и писать файлы проекта. Генерацию владелец запускает сам — бриф готовится так,
чтобы его оставалось вставить.

## 2. Бриф

```
Экран: <название и зачем он пользователю>

Что на нём есть: <список содержимого с настоящими примерами данных — самый
короткий и самый длинный случай>
Главное действие: <одно>
Состояния: <пусто, загрузка, ошибка, очень много данных>
Размеры: <целевые экраны из docs/DESIGN.md, раздел 5>

Собрать из компонентов дизайн-системы проекта. Нового компонента не заводить,
если подходит готовый.
```

## 3. Приёмка (`/add design`)

Файлы макета читаются из проекта Claude Design и кладутся в
`design/mockups/<экран>/`. Макет — **образец, а не код**: в очередь идёт пункт
`[ui]` «собрать экран по макету», и `designer` пишет по нему спецификацию для
настоящего стека. {{для веб-проекта: что из HTML макета можно переносить
напрямую}}
