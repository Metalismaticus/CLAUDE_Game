## Принято без полной проверки

Пополняет `/done` из строк `Ограничение:` и «вид не проверен»: пункт, дата,
чем ограничено. Запись снимается только ссылкой на проверку, которая это
покрыла.

## Нестабильные проверки

Проверка, красная 1–2 раза из 3 повторов, — сюда: имя, дата, как часто. Продукт
по ней вслепую не чинить — сначала сделать проверку устойчивой.

### Правила каркаса

- проверка без единого утверждения — провал;
- ошибка скрипта во время проверки — провал, если её явно не разрешили;
- пропуск — только с причиной;
- пустой вывод или ненайденный движок — красное;
- итог перечисляет каждый провал поимённо;
- у каждой команды предел времени (замер × 3), зависание — красное (код 124).

### Как добавить проверку

{{шаги и образец. Правило: новая проверка должна быть красной без исправления

### Красное, которое бывает правильным

Проверку заводят и на открытый баг — тогда она красная намеренно и стережёт
починку. Прежде чем «чинить красное», сверить с `BUGS.md`. Такую проверку
нельзя убирать или ослаблять ради зелёного итога.

## Параллельная работа

**Состояние: {{не проверено | проверено | невозможно}} · пишут: {{1}} · тяжёлых проверок: {{1}}**

`/start` делает независимые пункты одновременно, каждый в своей копии проекта
(git worktree), только при состоянии «проверено» и `пишут` больше 1. Решает по
пунктам разведчик `scout`; сомнение — по одному.

- `пишут` — сколько пунктов пишется одновременно: 0 или 1 — всё по одному; 2,
  3, 4 … — до стольких разом. `/parallel N`, на один запуск — `/start all xN`.
- `тяжёлых проверок` — сколько полных и долгих прогонов идёт одновременно,
  обычно 1: в `/start all` проверяющие пунктов работают в лёгком режиме, а
  полная и долгая идут один раз, в основной папке в конце партии.
  `/parallel проверки M`.
- Проверить числа пробным прогоном — `/parallel проверить`.

### Набор копий

Копии — `../<папка проекта>.wt/slot<K>`, по одной на пишущий пункт. Первый
раз слот создаётся (`git worktree add -b wave/p<N> <slot> main`) и готовится
по «Подготовке копии», дальше переиспользуется между волнами партии:

```bash
git -C <slot> reset --hard
git -C <slot> clean -fd
git -C <slot> checkout -B wave/p<N> main
```

`clean` без `-x` не трогает файлы из `.gitignore` — подготовленные кэши,
зависимости и локальная настройка копии остаются, если они там; всё, что
кладёт подготовка, должно быть в `.gitignore`. Страж коммитов разрешает
`reset --hard` и `clean` только в копиях `*.wt/…`. Что повторить в
переиспользованной копии, если менялись зависимости или ресурсы: {{… или
«ничего»}}.
