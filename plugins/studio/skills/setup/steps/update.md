# Развёрнутый проект: `/setup обновить` и повторный `/setup`

`/setup` без «обновить» в развёрнутом проекте — окно «Проект уже развёрнут —
что делаем?»: «Обновить процесс (Recommended)» — перенести новый шаблон,
проектное не трогать / «Пересмотреть старт» — стек, образцы или очередь:
покажу, что изменится / «Ничего» — выйти.

## Обновить процесс

1. Идёт партия (`docs/BATCH.md` не «Пусто.») — не обновлять до `/done`,
   кроме недостающих `tools/` из п. 5 (скрипты и `perf_ref.json`): их
   разложить сразу, отдельным коммитом. В нужных файлах чужие
   незакоммиченные правки — сначала завершить их.
2. Метка — из комментария `шаблон vN` в `CLAUDE.md` проекта (нет — v1); та
   же, что в `templates/CLAUDE.md`, — «процесс свежий», перейти к п. 5.
   Сравнить с шаблонами только **процессные** разделы:
   - `CLAUDE.md`: «Команды», «Два чата», «Как приходит работа», «Метки
     пунктов очереди», «Правила процесса», «Как спрашивать владельца» (список
     — из комментария-метки шаблона); свои строки проекта в них — в список
     «пропадут» (п. 3). «Какой документ когда» и «Git» — только недостающие
     строки шаблона, строки проекта не трогать и в «пропадут» не включать;
     «Git» нет — вставить после «Запуск и проверка» (п. 7);
   - `docs/TESTING.md`: «Параллельная работа», «Правила каркаса», «Ловушки
     стека», «Принято без полной проверки», «Нестабильные проверки»; строка
     «Канонические ракурсы», столбец «Сколько идёт · предел» и строки
     «сценарий игрока», «стенд ощущения», «замеры», «сборка», «проверка
     сборки» в «Командах проверки»; правило зондов в «Замерах»; разделы `##
     Сценарии игрока`, `## Стенд` (был `## Стенд вида`), `## Выпуск` и `##
     Окружение` (со строкой Context7); строка «Как открывается окно» и у
     продукта с миром в реальном времени (игра, стенд, просмотрщик) `##
     Бюджет производительности` — только если их нет (п. 4);
   - `docs/BATCH.md`: шапка и столбцы таблицы;
   - `docs/ROADMAP.md`: формат пункта «Подробностей ближайших пунктов»,
     метки маршрута и `[этап N]`, пояснение и формат «Этапов» и «Покрытия
     замысла» (этапы и строки — проектное). Нет «Этапов» — не вставлять
     пустыми: без них команды работают как раньше, собирает их `/roadmap`
     (п. 6). «Из плана владельца» пустой — убрать, с записями — оставить:
     `/roadmap` разложит их по этапам или в «Потом».
3. Разницу по разделам («было → станет») — во временный файл вне проекта,
   отдельно — строки проекта, которые пропадут при замене. В чат — путь и
   2–3 строки сути, затем окно «Применить (Recommended) / Показать подробнее /
   Не сейчас». «Показать подробнее» — открыть файл и спросить снова; «Не
   сейчас» — ничего не менять.
4. «Применить» — недостающее вставить, процессные разделы заменить текстом
   шаблона со значениями проекта (ветка, отправка), в «Какой документ когда»
   и «Git» дописать недостающие строки. Проектное не трогать:
   стек, «Правила проекта», очередь, записи, команды проверки, заполненные
   подразделы «Параллельной работы». Строку состояния перевести: `предел: N`
   → `пишут: N · тяжёлых проверок: 1`. `## Стенд`: был `## Стенд вида` — его
   текст и состояние становятся частью «вид»; не было — «вид» `нет` (мира,
   который судят глазом, нет — «не нужна: …»); часть «ощущение» — `нет` (без
   управления и камеры — «не нужна: …»); `## Сценарии игрока` и
   строки новых команд — «нет», не игра — «не нужен: …»; строка «замеры»:
   группа «замеры» идёт в «полной» — вынести её оттуда сюда (правка команд
   проверки — строкой «Решено за вас»), группы нет — «нет — строит пункт
   «замеры по бюджету»» (п. 9); `## Выпуск` — «нет — до первого выпуска»;
   `## Окружение` — заполнить по `env.md` (поставить
   что-то и Context7 — только окном, как там); нет в «Стеке» `CLAUDE.md`
   строки «Движок:» — дописать. `## Бюджет производительности` (мир в
   реальном времени; есть — проектное, не трогать): «Цели для игроков» —
   ответ вопроса окна п. 3 (`talk.md`, быстрый старт: один вопрос пакетом);
   прежние решения владельца о скорости (`DECISIONS.md`, «Производительность»;
   ограничения `CONCEPT.md`) главнее — их числа в строку своего уровня (о его
   компьютере — «машина владельца») с датой решения, расходятся с вариантом
   окна — назвать в его description; «Бюджет систем» — по «Замерам» проекта
   с пометкой «оценка до первого замера», нечего взять — «?? после первого
   замера»; «Машины замера» — по `env.md`, «Итог», и `tools/perf_ref.json`;
   другая машина владельца в «Замерах» (ноутбук) — строка «Не блокер»
   `BLOCKED.md` о калибровке («Машины замера» шаблона); «Как открывается
   окно» — по `testing.md`, п. 10, непроверенный флаг — «не проверено:
   <флаг>». Игра без раннера сценариев — в отчёт: пункт «Довести проверки:
   сценарии игрока через ввод» поставить через `/idea`.
   `{{…}}` вставленного — из проекта, неизвестное — `?? нужно подтверждение`;
   окном — только решение владельца (здесь — «Цели для игроков»),
   техническое — без окна. Поднять метку до метки шаблона.
5. Недостающие файлы — создать по шаблонам, показав список: `docs/`,
   `docs/refs/INDEX.md`, `tools/roadmap_check.py`, `tools/refs_check.py`,
   `tools/look_sheet.py` (если мир судят глазом), `tools/perf_ref.json`
   (мир в реальном времени), `tools/asset_check.py` и
   `docs/orders/ledger.md` (есть `docs/orders/` или это игра), `docs/.gdignore` у Godot, README (п. 7); в
   `docs/DECISIONS.md` нет раздела «Прогноз» — вставить его из шаблона.
   Скрипты `tools/`, которые есть, но отличаются от шаблонных, — заменить
   шаблонными (в том же списке); `tools/perf_ref.json` — не заменять:
   недостающие строки шаблона дописать, строки проекта (калибровка,
   добавленные машины, `levels`) оставить. Уже лежащие в git ассеты — в журнал тем, что известно из
   `docs/prompts/` и `docs/BLOCKED.md`, состояние `принят <сегодня>`;
   неизвестное (тариф, лицензия) — `не выяснено`, как велит `ledger.md`, не
   выдумывать.
   Нет `.gitattributes` — предложить отдельным вопросом в том же окне или
   своим (что в нём и почему — `plan.md`, шаг 8); после него файлы могут
   стать «изменёнными» — перевести их отдельным коммитом `git add
   --renormalize <файлы поимённо>`, пометка `Process:` / `Процесс:`
   («Process: Use the same line endings in all files» / «Процесс: единые
   концы строк во всех файлах»).
6. **Чужие карты.** До окна п. 3 найти в корне и `docs/` файлы плана —
   `GAME_ROADMAP.md`, `*ROADMAP*.md`, `*PLAN*.md` (кроме `docs/ROADMAP.md`,
   `SETUP-PLAN.md`, `ROADMAP-PLAN.md`), раздел «Порядок работ» в замысле — и
   второй замысел рядом с `CONCEPT.md`. Есть — вопрос в том окне (процесс
   свежий — своим): «Перенести в «Этапы» через `/roadmap` (Recommended)» /
   «Оставить отдельно» — строка в «Как ведётся работа» `DECISIONS.md`: `-
   <дата>: <файл> — отдельный план, в «Этапы» не переносим` (у замысла —
   `отдельный замысел`) / «Не трогать» — спрошу в следующий раз. Файл с
   такой строкой — не спрашивать, строкой в отчёт. Сами файлы не править;
   «Перенести» — последней строкой отчёта предложить `/roadmap`, молча не
   запускать. Нет ни их, ни «Этапов» — в отчёт «разложить замысел на этапы —
   `/roadmap`».
7. **Git и README** — до окна п. 3. В «Git» `CLAUDE.md` нет строки
   `Язык коммитов:` или `README:` — сначала по проекту, строкой «Решено за
   вас»: язык коммитов назван в «Правилах проекта» — записать его; есть и
   `README.md`, и `README.ru.md` — `en + ru`. Остальное — вопросы из
   `talk.md`, раунд (д) (рекомендация — `English`, `en + ru`; старая
   история коммитов остаётся как есть). README — по ответу и
   `../../reference/COMMITS.md`: нет файла — создать из шаблона (п. 5); есть
   с метками — обновить блоки без вопроса; есть **без меток — не
   переписывать**: собрать блоки, «было → станет» — в файл разницы п. 3.
   Места: `pitch` и `status` — сразу под заголовком, остальные — в конец;
   под заголовком же — строка-ссылка на второй язык, если в первых 10
   строках нет ссылки на `README.ru.md` / `README.md`. Раздел того же
   смысла (и текст между заголовком и первым `##` — это смысл `pitch`) не
   заменяется: в файле разницы — «похожий раздел: <имя>». Вопрос —
   «Описание проекта (README): вставить блоки, которые команды будут
   обновлять сами?» — `Вставить блоки (Recommended)` — добавлю блоки, ваш
   текст не трону / `Вставить и заменить: <разделы поимённо>` — эти разделы
   уйдут, их текст — в файле разницы (только если похожие есть) /
   `Показать подробнее` — открою разницу и спрошу снова / `Не трогать
   README` — строка в «Как ведётся работа» `DECISIONS.md`: `- <дата>:
   README — без блоков studio`; с ней не спрашивать. Второй язык (по строке
   «README:») — только вместе со вставкой блоков или к `README.md` с
   метками: по шаблону `templates/README.ru.md` (`README.md`), вне меток —
   только заголовок и ссылка, вступление — это `pitch`.
   Вопросы п. 4–7 — в окне п. 3 (процесс свежий — своим), пока их там ≤ 4;
   не влезают — первым окном «Применить» и компьютеры игроков, остальное —
   вторым окном сразу. Ответ о компьютерах игроков записать в
   `DECISIONS.md` и при «Не сейчас» (коммит `Процесс:`). About — собрать в
   «Git»; изменился и есть удалённый на GitHub — строками в отчёт, как
   `SKILL.md`, шаг 12.
8. Пункты очереди, похожие на `[вид]` (свет и небо, вода, растительность,
   местность, постройки, персонажи, эффекты, анимация) или `[ощущение]`
   (управление, камера, темп, звук, отдача), и паспорта `механика` про
   управление, камеру или звук не перемечать самому — перечислить в отчёте:
   «переметить и разобрать образцы — `/idea`».
9. **Находки — в очередь без окна.** В `docs/BATCH.md`, «Найдено по ходу»,
   если их нет ни там, ни в очереди (технические: `/idea` ставит их сам,
   строкой «Принято по умолчанию»). Искать по всему коду (и `scripts/`, не
   только `tests/`), прослеживая, откуда число в утверждении; по строке на
   дефект:
   - порог FPS в проверке под `--headless` или по счётчику за секунду (у
     Godot — `Engine.get_frames_per_second`, `Performance.TIME_FPS`) —
     «<имя>: порог FPS ничего не стережёт — порог убрать, остальные
     утверждения оставить в полной, скорость — сценарием группы «замеры» в
     окне»;
   - порог в мс внутри полной — «порог времени в полной (<имя>) — вынести в
     «замеры»»;
   - маршрут замера по реальному времени — «<имя>: маршрут — на
     `--fixed-fps`»; часы кадра вместо времени CPU и GPU рендера — «<имя>:
     часы кадра — на время видеокарты»;
   - C# в Debug без оптимизации — «замеры C# идут без оптимизации —
     собирать с `-p:Optimize=true`»;
   - команды проверок и снимков с окном поверх всех или с фокусом — «окна
     проверок не мешают работе»;
   - мир в реальном времени без группы «замеры» по бюджету — «замеры по
     бюджету».
   3D-мир без «Настроек графики» в очереди и «Сделано»: пресеты в коде уже
   есть — «Настройки графики: довести — ультра, ползунки лестниц,
   автоподбор под компьютер игрока», нет — «Настройки графики: пресеты из
   лестниц качества, автоподбор под компьютер игрока (`/setup обновить`)»;
   её `/idea` покажет владельцу: это видит игрок.
10. Один документальный коммит, файлы поимённо, пометка `Process:` /
    `Процесс:` (и у коммита `tools/` из п. 1): «Process: Adopt studio
    template v<N>» / «Процесс: шаблон studio v<N>», где <N> — метка
    шаблона; `docs/BATCH.md` с находками п. 9 — своим коммитом `Batch:
    Findings from the template update` / `Партия: находки /setup
    обновить`; отправить, если в `CLAUDE.md` коммиты отправляются. Затем самопроверка стража и короткий отчёт — `SKILL.md`,
    шаг 12; находки п. 9 — одной строкой.

## Пересмотреть старт

Не переписывать документы, а показать, что меняется:

1. Прочитать `docs/DECISIONS.md`, `## Старт` (нет — собрать из DECISIONS,
   CONCEPT и «Окружения» TESTING).
2. Окно `multiSelect` «Что пересматриваем в старте проекта?»: Стек / Образцы
   и вид / Замысел / Очередь.
3. Пройти только нужные шаги: стек — `env.md` и раунд (г); образцы —
   `refs.md`; замысел — раунды (а) и (б), есть «Этапы» — затем `/roadmap
   пересмотр`; очередь — `plan.md`, шаг 9.
4. `docs/SETUP-PLAN.md` — «было → станет» по документам и что из сделанного
   устареет (пункты, код, проверки). Путь и окно «Применить (Recommended) /
   Показать подробнее / Не сейчас».
5. «Применить» — точечные правки; каждая — строкой в `## Старт` с датой и
   «было: …». Переделку кода — пунктами очереди, необратимое — `[ждёт «да»]`.
   Коммит поимённо, пометка `Process:` / `Процесс:`, план удалить.
