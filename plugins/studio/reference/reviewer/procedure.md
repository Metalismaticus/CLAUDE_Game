# Порядок

Глава протокола субагента — читать, дойдя до этого этапа; после сжатия контекста перечитать. «п. N» — пункты главы «Порядок» (`procedure.md`).

1. `CLAUDE.md` проекта — уже в твоём контексте (Claude Code отдаёт его субагенту сам), не перечитывать — судить по «Правилам проекта» и «Правилам кода». Прочитать строку пункта в
   `docs/BATCH.md`, описание в `docs/ROADMAP.md` («Слова владельца», «Готово,
   когда», «Не входит») или запись в `docs/BUGS.md` («Где», «Нельзя ломать»);
   у обоих — строки «Не принят» и «Замечание владельца во время партии»: там
   причина отказа и где владелец видел проблему; «Архитектуру»
   `docs/CONCEPT.md`; относящиеся решения в `docs/DECISIONS.md`,
   `docs/TESTING.md`. У `[вид]` и `[ощущение]` — ещё паспорт целиком,
   картинки `[вид]` — до п. 2 (раздел «Режим `[вид]`»).
2. `git status` и `git diff` по файлам пункта. Каждое замечание — из
   четырёх частей: `[основание] файл:строка — что не так (наблюдаемый
   симптом) — готово, когда: <проверяемый признак>`; без файл:строка
   замечания нет (вкус — в «Вне круга»); исполнитель на круге 2–3 правит
   ровно до «готово, когда» — признак должен быть проверяемым. Проверить:
   - каждый кусок критерия действительно сделан; «Не входит» не тронуто;
     ничего сверх просьбы (новый файл для вынесенного из файлов пункта,
     вынос куска, который пункт повторил бы, функцией с вызовом на месте
     оригинала и новые файлы переноса у `Уборка:` — не сверх просьбы);
   - у бага цело всё из «Нельзя ломать»;
   - у `[баг]` в diff, в тех же файлах пункта, есть постоянная проверка,
     которая краснеет на этом классе дефекта (не на одном воспроизведении)
     и которую реестр находит сам; нет — CHANGES_REQUESTED `[критерий N]`
     «починка без проверки на дефект»; «неприменимо» исполнителя — только с
     причиной: тогда `Ограничение: баг без постоянной проверки — <причина>`;
   - нет чужих файлов и правок документов — исполнителю их трогать нельзя;
   - «Правила проекта» из `CLAUDE.md` — каждое, поимённо;
   - «Правила кода» (только если такой раздел в `CLAUDE.md` есть; нет — всё
     ниже лишь «Вне круга: уборка: …») — CHANGES_REQUESTED `[правило кода]`
     (файл:строка и что вместо) **только по признаку, который можно
     показать**: находка `code_check --changed` в файлах пункта (и в чужом
     файле: «… в старых строках» — тип там отнял этот diff, вызов по имени —
     его цель этот diff удалил); скопирован кусок, который уже есть (путь
     оригинала); одно число или правило игры теперь в двух местах
     (оба пути; кроме копии на языке без общего вызова — шейдер, другой
     процесс — с проверкой равенства: уже в «Копиях» `docs/CONCEPT.md` или
     со строкой `CONCEPT, Копии` в итоге; вторая копия на другом языке того
     же процесса (GDScript ↔ C#) исключением не служит, даже в «Копиях»;
     правка обеих половин старой копии — «Вне круга: уборка: …»); новое
     свойство сущности — ещё одним массивом рядом, а не полем типа (у
     сущности без типа исполнитель должен был вернуть «не удалось: код —
     <сущность> без типа»); новая запись с известными полями — словарём
     (словарь на границе GDScript ↔ C# — как в «Здоровье кода»
     `docs/TESTING.md` — и пресет варианта «параметр → значение» — не
     запись: новый ключ туда можно, имя ключа — константой);
     новая система дописана в чужой файл вместо своего; новая проверка —
     строкой в общем списке, хотя раннер находит сам; нарушена граница
     «Архитектуры». Старое, чего diff не касался, — «Вне круга: уборка: …»;
     новая абстракция с одним потребителем — «Вне круга», не отказ; «можно
     красивее» без признака — не замечание;
   - пункт `Уборка:` — «Готово, когда» выполнено по `code_check.py --only
     <файл пункта>`: находки больше нет, у заметки о размере — число в
     строке ниже прежнего, у реестра и раннера (держат список проверок или
     содержимого) — новое добавляется без строки в нём; те же проверки
     зелёные, утверждения не ослаблены — судить по самим утверждениям: тот
     же набор проверок с прежними именами, те же сравниваемые величины,
     условия и тексты провала — иначе `[критерий N]`. В файлах проверок
     можно: типы объявлений, шаг — в помощник с именем и вызовом на месте,
     повтор — вызовом из `tests/lib/`, `_закрытое` → открытый метод; у
     уборки, цель которой — перенос (раннер, разнесение по файлам), — только
     перенос и механическая правка вызова, без которой перенесённое не
     работает на новом месте (`process_frame` → `tree.process_frame`);
     правка вне названных файлов или новое поведение — `[сверх просьбы]`;
   - новый код подключён: его вызывает продукт, а не одна проверка;
   - на экране нет литерала-заглушки; нет TODO/FIXME/«временно» без номера
     пункта; нет «пока», «упрощённо», «на потом», ослабляющих критерий;
   - проверка пункта есть и ловит исправленное; ожидаемые числа в ней взяты
     из критерия, а не пересчитаны так же, как в коде;
   - проверка с порогом кадров или времени — в группе «замеры», по времени
     кадра (p99, рывки) против «Бюджета производительности», не по
     `Engine.get_frames_per_second`, `TIME_FPS`, `TIME_PROCESS` или среднему
     FPS, C# оптимизирован (экспорт или `-p:Optimize=true`); команды
     запуска, которые пункт добавил или изменил, — по «Как открывается окно»
     (окно поверх всех, с фокусом или на экране там, где не нужно, — брак). Иначе
     CHANGES_REQUESTED `[спецификация]`. Строки «Как открывается окно» нет —
     окна не судить: «Вне круга: окна проверок — `/setup обновить`»;
   - управление, интерфейс, действия игрока — сценарий через ввод («Сценарии
     игрока» `docs/TESTING.md`) есть и **нажимает** (действия, кнопки по
     тексту), а не вызывает функцию; утверждает по именам и группам объектов;
     шаги и числа — из «Готово, когда». Нет — CHANGES_REQUESTED `[критерий
     N]`, если «Готово, когда» записано шагами игрока, иначе
     `[спецификация]`; раннера нет — `Ограничение: управление проверено без
     ввода — нет раннера`.
3. Запустить **ровно по одному разу**. В `tools/check_plan.json` заполнен
   список `checks` — свои прогоны единым входом `python -X utf8
   tools/run_check.py --root <путь> --mode <режим> [--check <имя>] [--areas
   <области>]`: проверка пункта — `item`, её группа — `affected`, быстрая —
   `quick`, полная — `full`, долгая — `long` (в лёгком режиме — `item`,
   `affected` и `quick`); код 3 — «мало места» — не красное: вердикт по тому, что
   прогнано, и `Ограничение: мало места — <причина из вывода>`. План пуст
   (`checks: []`) или скрипта нет — командами из таблицы `docs/TESTING.md`,
   как раньше:

   | Маршрут | Что гонять |
   |---|---|
   | `[код]`, `[баг]` | проверку пункта, полную, быструю; относящуюся долгую, если она есть |
   | `[ui]` | то же и снимки — п. 4 |
   | `[вид]`, `[ощущение]` | стенд, основу и встраивание — как `[код]` (у `[вид]` — и снимки п. 4); выбор — проверку пункта, быструю и режим своей метки |
   | `[данные]` | проверку пункта, быструю и «после правки ресурсов»; полную не гонять |

   Во всех маршрутах и в лёгком режиме — ещё «здоровье кода» и «типы», если
   строки есть: секунды, окна нет.

   **Лёгкий режим** (по слову координатора): проверка пункта, её группа и
   быстрая; полную и долгую не гонять, в итог —
   `Ограничение: лёгкий режим — полная проверка в конце партии`.

   Зелёный прогон исполнителя не повторять только когда в его итоге названы
   команда, папка и результат и ни файлы, ни команда с тех пор не менялись;
   «зелёное на словах» не считается — гонять самому.

   Вердикт читать так, как сказано в столбце «Как читать вердикт»: коду
   возврата верить только там, где он назван честным. Красное на проверке,
   которую пункт не трогал, — повторить до трёх раз: красная 1–2 из 3 —
   нестабильная, в «Вне круга», продукт ею не валить; красная всегда — сверить
   с `docs/BUGS.md` (бывает намеренной) и назвать отдельной строкой. Проверки
   тона и края, которые пункт света переписал по «Готово, когда» на
   утверждения паспорта света («снято до света»), — его критерий, не
   ослабление: судить по утверждениям паспорта, прежних чисел не требовать.
4. **Снимки — для любого пункта, критерий которого про вид.** Командой «снимок
   экрана» (у `[вид]` — «снимок кадра») из `docs/TESTING.md`: сначала **место
   владельца** — «Как увидеть», «Где» записи бага, строки «Не принят» и
   «Замечание владельца во время партии», у `[ui]` — «Где снимать»
   спецификации (экран, seed, регион, координаты); затем канонические ракурсы
   `docs/TESTING.md`, у `[вид]` — кадры паспорта, у `[ui]` — целевые размеры
   `docs/DESIGN.md`. Снимки и прогоны с рендером — на пресете графики
   «высокие» (настроек графики нет — единственном; стенд не умеет пресет
   аргументом — на том, какой есть, не брак: «Пресет: <какой> — стенд не
   умеет», «Вне круга: стенду — пресет аргументом»), в итоге — строка
   «Пресет». Каждый снимок — сначала `python -X utf8 tools/look_sheet.py
   --sanity <png>…` (все снимки и варианты круга, прошлый круг — как
   принимает скрипт): код 1 — брак без обсуждения, CHANGES_REQUESTED
   `[спецификация]` со строкой скрипта; режима нет — «Вне круга: проверки
   кадра нет — `/setup обновить`». Затем открыть (Read) и до чисел написать
   «Вижу: <снимок> — <что в кадре словами продукта: предмет, форма, края,
   что не так>» — словами, которые понял бы владелец («плоский
   многоугольник с прямыми краями», «мягкая шапка без граней»); потом
   сверить с критерием, у `[ui]` — и с «По чему судить снимок» и
   `docs/DESIGN.md` (сетка, шрифты, акцент, наложения и обрезка,
   состояния). Снимки и свой лист — в
   `<папка проекта>.wt/shots/<дата>-p<N>-r<R>/` рядом с проектом (из копии —
   `../shots/…`): не в проекте и не в копии, её чистят. Места нет или снимок
   расходится с критерием — CHANGES_REQUESTED `[критерий N]`. Команды снимка
   нет — одобрять можно, с `Ограничение: вид не проверен — снять нечем`, в «Не
   судил» — что посмотреть глазом.
5. Полигон не «есть» — проверить названное в «Что проверяется уже сейчас» и
   написать в «Ограничение», чем одобрение ограничено.
6. Теперь прочитать итог исполнителя целиком (путь — в сообщении). Строка
   «Красное без исправления» должна совпадать с симптомом, а не быть ошибкой
   сборки. «Решено за вас», «Проверки», «Как увидеть», «Лист» расходятся с
   увиденным — замечание с основанием; нет основания — в «Вне круга».
   Заметка «служба <имя>» `code_check --changed` (новая автозагрузка) — в «В
   документы при /done» итога строка `CONCEPT, Службы: <имя> — <что
   хранит>`; нет — CHANGES_REQUESTED `[правило кода]`.
7. О чём критерий молчит (вкус, неописанное) — не судить: строка «Не судил»,
   это глазу владельца. У `[вид]` главная ось названа «Разрывом» паспорта —
   по ней не «Не судил», а «По разрыву» (режим `[вид]`, п. 3).
