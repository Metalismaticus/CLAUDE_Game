# Коммиты, README и About проекта

Общие правила для всех команд и агентов studio, которые пишут сообщения
коммитов, `README.md` проекта или строку About. Скилл ссылается на этот файл
одной строкой и правила не копирует. История коммитов и README — то, что
люди видят на GitHub: по первой строке коммита понятно, что изменилось в
игре, по README — что это за проект и что в нём уже работает.

## Язык

Строка `Язык коммитов: English | Русский` в разделе «Git» `CLAUDE.md`
проекта; её пишет `/setup` (и `/setup обновить`) после окна, рекомендация —
`English`. Нет строки — язык последнего коммита пункта (`git log -1 -E
--grep "^(Пункт|Item) [0-9]+:" --format=%s`): кириллица — Русский, иначе
English; коммитов пунктов нет — English. `/start` пишет язык партии в шапку
`docs/BATCH.md` (`Язык коммитов: …`), исполнитель берёт его оттуда. Тело
коммита — на том же языке. Старая история остаётся как есть, поэтому искать
— всегда обеими пометками (раздел «Поиск»).

## Пометки

Первое слово первой строки:

| Кто коммитит | English | Русский |
|---|---|---|
| пункт партии (`/start`, поправки) | `Item N:` | `Пункт N:` |
| таблица партии, итоги прогонов | `Batch:` | `Партия:` |
| приёмка (`/done`, документы по итогам) | `Accept:` | `Приёмка:` |
| очередь и замысел (`/idea`, `/need`) | `Queue:` | `Очередь:` |
| образец (`/idea`, `/need` — только образцы; концепт стиля в `/idea` — и с очередью и заказами; агент `reference` не коммитит, коммит — позвавшего) | `Reference:` | `Образец:` |
| баг (`/fault`) | `Bug:` | `Баг:` |
| заказ (`/order`) | `Order:` | `Заказ:` |
| пришедшие файлы (`/add`) | `Assets:` | `Ассеты:` |
| процесс (`/setup`, `/parallel`, `/check`, `/retro`) | `Process:` | `Процесс:` |
| карта (`/roadmap`) | `Roadmap:` | `Карта:` |
| выпуск (`/release`) | `Release:` | `Выпуск:` |
| откат | `Revert "…"` — как пишет git | так же |

У пометки пункта — один номер: правка сразу двух пунктов — два коммита, по
коммиту на пункт (`Пункт 4 и 9:` поиск не находит).

## Первая строка

- Не длиннее 72 знаков вместе с пометкой.
- После пометки — **что изменилось для игрока или пользователя**, простыми
  словами. English — повелительное наклонение, с заглавной после пометки
  («Item 3: Let players dig through stone with a pickaxe»); русский — «что
  сделано» («Пункт 3: копать камень киркой»).
- **Нельзя:** метафоры и «художественность» («keep the other nine
  moving»); пустые слова (`fix`, `update`, `changes`, `misc`, `wip`,
  «правки»); имена констант, файлов и функций — они в теле.
- Служебный коммит (`Batch:`, `Process:` …) — что случилось с работой, так
  же просто; числа — в теле.

| Нельзя | Так |
|---|---|
| `Item 4: Bake the light into the faces, countable before the press` | `Item 4: Add a Bake button that paints outline and shading into colours` |
| `Process: Keep the other nine moving` | `Queue: Put the desktop app on hold until its toolchain is chosen` |
| `Партия: итоговые прогоны — полная 66/0, быстрая 1/0` | `Партия: итог запуска`, числа — в теле |
| `Item 2: fix water` · `Пункт 2: правки` | `Item 2: Stop water from flooding the cave` · `Пункт 2: вода не заливает пещеру` |
| `Item 5: Raise JUMP_HEIGHT in player.gd` | `Item 5: Let the hero jump onto crates` |

## Тело

После пустой строки, строки до ~72 знаков, 1–5 строк: зачем; что теперь
видно (из «Как увидеть»); проверки (`Checks: full 66/0, quick 1/0` /
`Проверки: полная 66/0, быстрая 1/0`); на какой пункт или баг это ответ.
Технические подробности — здесь. Слова владельца — дословно, в кавычках, на
его языке. **Строку тела с пометки не начинать**: поиск находит любую
строку. Тело — следующими `-m`, по абзацу на каждый `-m`. Файл сообщения
(`-F`) не использовать: PowerShell пишет его с BOM, первая строка перестаёт
начинаться с пометки, и поиск коммит не найдёт. После коммита сверить
`git log -1 --format=%s`: строка начинается с пометки.

```
Item 3: Let players dig through stone with a pickaxe

Stone breaks after three hits and cracks after each one.
To see: new world, seed 42, cave at 10,5 - hit the wall three times.
Checks: full 66/0, quick 1/0.
For batch item 3, "Mining" in the queue.
```

```
Пункт 3: копать камень киркой

Камень ломается с трёх ударов, после каждого видна трещина.
Как увидеть: новый мир, seed 42, пещера у 10,5 — ударить стену трижды.
Проверки: полная 66/0, быстрая 1/0.
К пункту 3 партии, «Добыча» в очереди.
```

Одна правка — один коммит; файлы — поимённо.

## Постоянные сообщения `/start` и `/done`

| Что | English | Русский |
|---|---|---|
| стенд | `Item N: Add the look stand` · `Item N: Add the feel stand` | `Пункт N: стенд вида` · `Пункт N: стенд ощущения` |
| варианты к выбору | `Item N: Offer <тема> variants, choice K` | `Пункт N: варианты <тема>, выбор K` |
| поправка по слову владельца | `Item N: Rework — <что изменилось>` | `Пункт N: поправка — <что изменилось>` |
| партия снята | `Batch: Take N items from the queue` | `Партия: снято N пунктов из очереди` |
| волна | `Batch: Start wave W with items N, M` | `Партия: волна W — пункты N, M` |
| пункт готов | `Batch: Mark item N ready for review` | `Партия: пункт N готов к проверке` |
| ждёт выбора | `Batch: Hold item N for the owner's choice` | `Партия: пункт N ждёт выбора` |
| выбор записан | `Batch: Record choice K for item N` | `Партия: пункт N — выбор K` |
| итог запуска | `Batch: Record run results` | `Партия: итог запуска` |
| приёмка | `Accept: <что теперь может игрок>` | `Приёмка: <что теперь может игрок>` |

У снятия партии в теле — волны; у итога запуска — числа прогона; у
приёмки — числа финальной проверки
и строка «Items kept: 1, 3; reverted: 2 — <причина>» / «Пункты оставлены: 1,
3; откат: 2 — <причина>».

## Поиск

Всегда `-E` и обе пометки. Коммиты пункта N партии (хеш — из строки
«Снята … на <хеш>» `docs/BATCH.md`):

```
git log <хеш>..HEAD -E --grep "^(Пункт|Item) N:"
```

- все коммиты пунктов — `-E --grep "^(Пункт|Item) [0-9]+:"`;
- откаты пункта N — `-E --grep "^Revert .(Пункт|Item) N:"`: поиск пункта
  их не находит; с каким коммитом откат в паре — строка `This reverts
  commit <хеш>` в его теле;
- стенд — `-E --grep "^(Пункт|Item) [0-9]+: (стенд|Add the (look|feel) stand)"`;
- прочие пометки — так же парой: `"^(Партия|Batch):"`,
  `"^(Приёмка|Accept):"`.

`^` — начало любой строки сообщения: у найденного сверить первую строку
(`--format="%h %s"`) — коммит, где пометка только в теле, не в счёт.

## README

- Файлы: `README.md` (English) и `README.ru.md` (русский); строка в «Git»
  `CLAUDE.md`: `README: en + ru | en | ru` (нет строки — `en + ru`). В
  начале каждого — ссылка на другой: «Русская версия: README.ru.md» /
  «English: README.md». Одно `en` или `ru` — только `README.md` на этом
  языке (его показывает GitHub), без ссылки.
- Обновляемые части — между метками `<!-- studio:begin <имя> -->` и
  `<!-- studio:end <имя> -->`. Всё вне меток — текст владельца, его **не
  трогать никогда**. Блоки:

  | Блок | Что в нём | Откуда |
  |---|---|---|
  | `pitch` | одна-две строки: что это и для кого | «Одной строкой» `docs/CONCEPT.md` |
  | `status` | «Now: Stage N — <что увидит игрок>», «Next: …» (по-русски — «Сейчас», «Дальше») | «Этапы» `docs/ROADMAP.md`; этапов нет — «Очередь» одной строкой |
  | `features` | «What works» / «Что уже умеет»: до 10 строк словами игрока | «Что работает» `docs/CONCEPT.md` и «Сделано» `docs/ROADMAP.md` |
  | `run` | требования и как запустить, без путей с именем пользователя | «Запуск и проверка» `CLAUDE.md`, «Окружение» `docs/TESTING.md` |
  | `shots` | до 3 снимков относительными ссылками; нет — блок пустой | `docs/refs/*/accepted-*` |
  | `release` | последняя версия и ссылка на `docs/releases/<версия>.md`; нет выпусков — блок пустой | `docs/releases/` |

- Кто обновляет: `/done` — `features`, `status`, `shots` в завершающем
  документальном коммите приёмки; `/roadmap` — `status` при записи карты и
  `следующий`, а при смене «Одной строкой» — ещё `pitch`; `/release` —
  `release`, `features`, `pitch`, `run`; `/setup` — создаёт оба файла из
  шаблонов; `/setup обновить` — обновляет блоки, а в README без
  меток вставляет их только по согласию владельца.
- Оба файла меняются вместе, одним коммитом, по смыслу одинаковы: в
  `README.md` — по-английски, в `README.ru.md` — по-русски. Словами игрока,
  без внутренней кухни (круги, партии, имена файлов кода).
- Нет файла или меток — сами блоки не вставлять: одной строкой в отчёт
  «README без блоков studio — `/setup обновить`»; в «Как ведётся работа»
  `docs/DECISIONS.md` есть строка `README — без блоков studio` — молча, без
  строки в отчёте.

## About

About на GitHub — два поля. Описание: English, ≤ 350 знаков, `pitch`
по-английски (что это, для кого, платформа), без этапа и версии. Темы: 3–6,
латиницей в нижнем регистре через дефис (`godot`, `voxel`,
`procedural-generation`). Хранятся в «Git» `CLAUDE.md`: `About: <описание>
· Topics: <темы>`. `/setup`, `/roadmap` (когда меняется «Одной строкой») и
`/release` пересобирают их; изменились и есть удалённый репозиторий на
GitHub (`git remote -v` содержит `github.com`) — в отчёте две строки:
«Обновите About на GitHub (шестерёнка справа от About) — Description:
<описание>» и «Topics: <темы через пробел>». Сами на GitHub ничего не
меняют и GitHub CLI ради этого не ставят.
